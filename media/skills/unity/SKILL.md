# Unity

Practical guide for building and modifying a Unity project with Claude Code agents. Use this skill whenever a task touches `Assets/`, `.unity` scenes, `.prefab` files, C# `MonoBehaviour` scripts, or asks to add a component, scene object, or ScriptableObject.

## When to use this

- The workspace has an `Assets/`, `ProjectSettings/`, and `Packages/` folder (the Unity project layout).
- The task mentions GameObjects, components, prefabs, scenes, C# scripts under `Assets/Scripts`, or the Unity Editor/Inspector.
- A `.sln`/`Assembly-CSharp.csproj` generated by Unity is present.

## Project structure & key files

- `Assets/` — all project content: scripts, scenes, prefabs, materials, art. Subfolder convention (e.g. `Assets/Scripts`, `Assets/Prefabs`, `Assets/Scenes`) is a team convention, not enforced by Unity.
- `*.unity` — a scene, serialized as YAML text. Contains GameObjects, their Transform hierarchy, and component references by GUID.
- `*.prefab` — a reusable GameObject template, also YAML. Instances in scenes reference the prefab by GUID and can override specific fields.
- `*.meta` — **one per asset**, holds the asset's stable GUID and import settings. These are how Unity resolves cross-references; they are not optional and must be committed alongside their asset (a missing `.meta` breaks every reference to that file).
- `*.cs` — C# scripts. A `MonoBehaviour` subclass becomes attachable as a component when it lives under `Assets/`.
- ScriptableObjects — `.asset` files backed by a `ScriptableObject` C# class; used for shared data (item definitions, config) that isn't tied to a scene instance.
- `ProjectSettings/` — project-wide config (input, physics, quality tiers) as text assets.

## Scripting model

Unity scripting is C# with a component-based architecture: behavior is composed by attaching multiple `MonoBehaviour` scripts to a GameObject, each handling one concern. Unity calls well-known lifecycle methods (`Awake`, `Start`, `Update`, `FixedUpdate`, `OnCollisionEnter`, …) automatically.

```csharp
using UnityEngine;

[RequireComponent(typeof(Rigidbody2D))]
public class PlayerMovement : MonoBehaviour
{
    [SerializeField] private float speed = 6f;
    [SerializeField] private float jumpForce = 9f;

    private Rigidbody2D _rb;

    private void Awake()
    {
        _rb = GetComponent<Rigidbody2D>();
    }

    private void Update()
    {
        float move = Input.GetAxisRaw("Horizontal");
        _rb.linearVelocity = new Vector2(move * speed, _rb.linearVelocity.y);

        if (Input.GetButtonDown("Jump"))
        {
            _rb.AddForce(Vector2.up * jumpForce, ForceMode2D.Impulse);
        }
    }
}
```

`[SerializeField]` exposes a private field in the Inspector without making it public; `[RequireComponent]` documents/enforces a dependency.

## Common tasks

- **New scene**: File > New Scene in the editor, or duplicate an existing `.unity` file and strip contents; add via `EditorSceneManager` if scripting the creation.
- **Add a component**: create a `MonoBehaviour` script under `Assets/Scripts/...`, then attach it to a GameObject in the Inspector (drag-drop or "Add Component").
- **Handle input**: legacy `Input` class (`GetAxis`, `GetButtonDown`) for quick prototypes, or the newer `Input System` package (`InputAction`/`PlayerInput`) for rebindable, multi-device setups — check `Packages/manifest.json` for which is installed before assuming.
- **Wire events**: `UnityEvent` fields exposed in the Inspector for designer-wireable callbacks, or C# `event Action` for code-only pub/sub.
- **Build/run**: Play button in-editor for iteration; `File > Build Settings` (or `-batchmode -quit -executeMethod` CLI invocation) for actual builds.

## Gotchas

- **`.meta` files must be committed** alongside their asset — deleting or renaming an asset outside the editor orphans its `.meta` and breaks every prefab/scene reference to it (shows up as "Missing Script" or a null reference).
- Prefab **overrides** — a scene instance can diverge from its prefab; large unintentional diffs in a `.unity`/`.prefab` file are often stray override noise, not real changes.
- `Update()` runs every frame and is not fixed-timestep — physics code belongs in `FixedUpdate()`.
- Renaming/moving a script class name must match the filename, or Unity refuses to compile/attach it.
- Domain reload on every script recompile resets non-serialized static state — don't rely on statics surviving a recompile during Play mode.
