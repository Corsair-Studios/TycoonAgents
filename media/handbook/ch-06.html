06

Generation & the Review Screen

From form to art
Once your form is filled in (Chapter 05), generation runs in a fixed order and hands you a review screen where you can retry individual items without burning spend on the whole theme.
§ 6.1 · Pipeline order
what generates when

Generation always proceeds in the same sequence:

01

Environment / background — generated first, since every other piece is composed against it.

02

Characters

03

Rivals

04

Decor

05

Objects

06

Expressions

07

Badges

A "Pause for review" toggle, when on, stops generation between boards so you can check each batch before moving to the next instead of waiting for the whole pipeline to finish.

§ 6.2 · The review screen
fix without regenerating everything

At the top of the review screen sits the Creative Direction editor. Edits here are persisted, but they only re-ground future regenerations — they never repaint art that's already been generated. If you change your mind about the theme's direction partway through, existing approved items stay exactly as they are.

Below that, every generated item gets its own collapsible name-and-description editor with a per-item Retry button — so a single bad character or object can be regenerated on its own instead of redoing the whole board. Approve all accepts everything currently shown, and Resume / Stop control whether the pipeline continues to the next board.

§ 6.3 · Resume and recovery
no wasted spend

If a board was accepted but its frames didn't make it to disk for some reason, Resume recovers it by re-slicing the stored raw image — it does not call the image API again, so there's no additional cost to recover from an interrupted session.

§ 6.4 · Where a theme is stored
on disk, per project

Themes are stored per-project inside your editor's global storage. Each theme is a self-contained folder holding manifest.json, plan.json, and frames.json, plus an images/ folder for finished art and an images/raw/ folder for the unsliced source images Resume draws from.

Note

Because raw images are kept alongside sliced frames, most generation hiccups are recoverable without spending API credits again. Chapter 07 covers the specific failure cases and fixes in more depth.

§ 6.5 · Turrets (optional)
give one animated object teeth

On the review screen's per-object editor, either of your theme's two animated objects can be marked "Acts as turret (auto-fires at attackers)". This checkbox only appears on animated object rows — static objects and decor don't get it. Turning it on is entirely opt-in: a theme that never checks the box behaves exactly as it does today.

A built turret auto-targets the nearest attacker in range and fires roughly once per second, reusing the projectile art you already described for that object — there's no separate turret sprite to generate. Each shot deals about a quarter of a character's damage and briefly staggers the target, interrupting whatever it was attacking. A turret is also a normal structure in every other sense: it takes damage, smokes when hurt, shows a health bar, and needs repairing like anything else you build. While it's damaged, it stops firing entirely and only resumes once fully repaired.

Tip

Turrets ride on the projectile description you already wrote for that animated object (Chapter 05, § 5.2), so there's nothing extra to generate. If the object's projectile art was skipped or never generated, marking it as a turret is harmless — it simply won't fire.
