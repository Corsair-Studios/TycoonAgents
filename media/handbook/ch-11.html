11Project Plan

Phases, gates, and human approval

Project Plan is an optional feature — on by default for new installs — that turns a design doc into a structured plan of phases and tasks, with a human approval gate before each phase and each task result. It's driven by the project-plan skill, so Claude does the decomposing; you do the approving.

§ 11.1 · How a plan is structured phases → tasks → acceptance criteria

A plan is a set of phases, each holding a list of tasks. Every task carries its own acceptance criteria, so "done" has a concrete definition rather than being a judgment call in the moment.

§ 11.2 · Gates and task states what the badges mean
Badge / stateMeaning
Phase gate — PendingThe phase hasn't been approved yet; work in it won't proceed.
Phase gate — ApprovedYou've approved the phase; its tasks can run.
Task — activeCurrently being worked.
Task — verifyingWork is done and is being checked against its acceptance criteria.
Task — doneVerified and accepted.
Task — needs_fixVerification found an issue; it needs another pass.
Task — skippedDeliberately skipped, at your direction.
§ 11.3 · Approving and steering work the buttons you'll actually use
01

Approve phase. Unlocks that phase's tasks so work can start on them.

02

Approve / Retry / Skip. Per-task actions on the task itself — approve a finished task, ask for a retry, or skip it outright.

§ 11.4 · When something looks stuck stall indicator & plan recovery

Warn

If an active task shows no hook activity for roughly five minutes, the panel flags it: "this task may be stalled. Ask Claude to resume the plan." This is a nudge, not an automatic action — you decide whether to resume it.

Note

If plan.json ever gets corrupted, the panel offers Restore last good, which restores from plan.json.bak — a snapshot kept alongside the live plan file.

§ 11.5 · Archived Plans read-only history

Completed plans move into an Archived Plans section — read-only, so you can look back at what a previous plan covered without it cluttering the active view.
