12UEFN Power Tools

For Fortnite Creative projects

If your workspace is a UEFN (Unreal Editor for Fortnite) project, TycoonAgents adds a second layer on top of everything else: a bridge into the editor itself, so agents can inspect and audit your level, not just your source files.

§ 12.1 · Setup detected automatically

The setup wizard detects a UEFN project on its own. When it does, it offers to:

01

Stage the Python bridge into your project's Content/Python folder.

02

Install the Verse Expert and UEFN Auditor agents alongside your other specialists.

Screenshot

Setup screen — UEFN detected, bridge staging chip.

See also

The UEFN chip in the stage's status chip row (Chapter 03, § 3.6) shows live bridge connectivity at a glance: green glow means a heartbeat arrived in the last 15 seconds and agents can use the uefn_* MCP tools; amber means reopen the project in UEFN so the bridge auto-starts.

§ 12.2 · The Power Tools window in-editor launcher

Once the bridge is staged, an in-editor launcher window becomes available inside UEFN itself. Its title bar shows the bridge's version, so you can tell at a glance whether it's current. From there you can reach:

ToolWhat it does
Device auditReviews devices in your level for common configuration issues.
Project health scanChecks the project for structural issues across its assets and Verse source.
Asset browsersBrowse and inspect assets in your project's content.
IP / Moderation ScanCollects the raw asset, Verse, and metadata surfaces Fortnite moderation may flag before submission. The launcher can only show the raw data — run the matching MCP tool from a connected AI assistant for the full analysed report.

Verse analysis

ToolPurpose
uefn_verse_checkRuns Epic's own Verse language server — the same analyzer bundled with the Verse VS Code extension — headless, for real compiler diagnostics. It's the only tool in this reference that works while UEFN itself is closed. It accepts a set of target files, and classifies every diagnostic's origin as project (your own code) or epic-generated (Epic's digest/cache files). A clean project can still report hundreds of epic-generated diagnostics — that's normal, and it means your own code is analyzer-clean.
§ 12.4 · Keeping the bridge current self-updating, mostly

The bridge keeps itself up to date in two ways: the newest project-side copy wins automatically when a UEFN project loads, and the extension also refreshes engine-side copies each time the panel opens.

Tip

If the Power Tools window's title shows an older version than your installed extension, close and reopen the UEFN project — the self-sync runs at project load, before anything else.

§ 12.5 · Revision control hygiene .urcignore

Setup also writes a .urcignore file so day-to-day dev artifacts (config, logs, and similar loose files) stay out of UEFN's Revision Control — only your actual project assets get tracked.

§ 12.6 · Device audit defaults comparison

The device audit diffs every device's properties against its class defaults, so it can show exactly what a creator changed versus what shipped as the default. The audit window's device list has a Tuned column showing how many properties differ from default for each device — when defaults can't be resolved for a class, that column shows a ? rather than a fake 0, so an unresolved comparison is never mistaken for "nothing changed."

Opening a device's detail view adds a Tuned Properties table listing each changed property alongside its current value and its class default. The same idea carries into the Property Inspector: every current value there is shown beside a Default column, so you can spot a tuned property without cross-referencing anything else.

Device listings also account for every actor rather than silently dropping ones that fail to resolve: skipped actors are counted, and a device with a field that fails to read is listed anyway, with an error note attached, instead of being omitted from the results.

§ 12.7 · Moderation self-verifying saves & thumbnail scope

Moderation report saves are self-verifying: after writing a report, the bridge re-reads back what it just wrote and only reports success once that round-trip passes. A save is never reported as landed on the strength of the write call alone.

Thumbnail pixel review is scoped to project-owned images only — engine and Fortnite built-in thumbnails are never scanned. The report states how many thumbnails were excluded for this reason, so the exclusion is visible rather than silent.
