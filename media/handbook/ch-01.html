Welcome & Concepts

Read this first
TycoonAgents watches your Claude Code multi-agent delegation and turns it into a living tycoon scene — agents that walk, build, and earn badges as your orchestrator hands off real work to specialists. This chapter covers the four ideas you need before anything else in this handbook will make sense.
§ 1.1 · What TycoonAgents actually does
the elevator pitch

TycoonAgents is a VS Code‑compatible extension. It does not run your project, and it does not decide how your agents work. Instead, it sits alongside Claude Code and observes: every time your orchestrator dispatches a task to a specialist agent, and every time that agent finishes, TycoonAgents' hooks record the event. The panel then replays those events as a scene — each agent is a character on a stage, walking to a build site, hammering away, and celebrating when the task completes.

The important part: this is a visualization of work that is already happening. TycoonAgents does not make your agents faster or smarter, and it never calls an AI model itself at runtime. It reads hook events and draws pictures. That's the whole contract.

§ 1.2 · Orchestrator vs. specialists
who does what

Claude Code multi-agent work in this project follows a simple split:

  • The orchestrator is the top-level agent you talk to. It reads the task, makes high-level decisions, and coordinates — but it does not do the implementation work itself.
  • Specialist agents are narrower workers (search, coding, testing, UI, and so on) that the orchestrator delegates to. Each one is scoped to a job it's good at, and many of them run on cheaper models than the orchestrator.

This split matters for cost as much as it matters for scene rendering: routing routine work (searching a codebase, running a quick check) to a small, cheap model instead of the expensive one doing the coordinating is the whole reason the delegation pattern exists. TycoonAgents' Metrics and Delegation tabs (Chapter 03, Chapter 10) exist specifically to make that cost split visible.

Tip

In the scene, the orchestrator is always the leader character in the first seat — easy to spot even in a crowded stage.

§ 1.3 · The delegation doctrine
how routing gets enforced

Delegation doesn't happen automatically just because specialist agents exist — it happens because your project's CLAUDE.md contains a delegation doctrine: instructions telling the orchestrator which kinds of work must be routed to which specialist, and forbidding it from doing that work directly. TycoonAgents installs this doctrine for you during first-run setup (Chapter 02), and it's the reason the scene has anything to show at all — no doctrine, no delegation, no agents walking around.

Two doctrine modes are available at install time: a flat Orchestrator mode, where one orchestrator dispatches directly to every specialist, and a hierarchical Team Lead mode, where work can fan out through an extra coordination layer. Chapter 02 covers picking between them.

§ 1.4 · Themes: generate once, render forever
where the art comes from

Everything you see on stage — characters, buildings, badges, backgrounds — comes from a theme: a bundle of generated art matched to a creative direction you choose (a neon-city theme, a high-seas theme, whatever fits your project or your mood). A theme is built once, using the Theme Maker's image-generation pipeline (Part II of this handbook), and stored locally. After that, the panel never calls an image API again — it just renders the stored frames. Generating art is the only part of TycoonAgents that talks to an external AI provider, and it only happens when you explicitly ask it to.

Note

TycoonAgents ships with ready-to-use themes so you can see the scene working before you generate anything yourself. Building your own theme is optional, covered starting in Chapter 04.
