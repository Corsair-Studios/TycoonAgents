10Settings Reference

Two layers of settings

TycoonAgents has editor-level settings (the ones your editor's Settings UI knows about) and an in-panel Settings tab with richer, live controls. This chapter lists both, so you know where to look for a given knob.

§ 10.1 · Editor settings key · default · what it does
Setting keyDefaultWhat it does
tycoonagents.autoShowtrueAutomatically opens the live agent panel when a workspace opens.
tycoonagents.idleFreezeMinutes3Freezes an agent's live time after this many minutes with no activity.
tycoonagents.sanityCapMinutes15Hard cap on any single active stretch, in minutes.
tycoonagents.providerclaude-codeWhich coding agent harness TycoonAgents reads activity from — claude-code or codex. The TYCOON_PROVIDER environment variable, if set, always overrides this.
tycoonagents.agents.multiProviderfalseShows vendor and fallback controls for every agent in the Agents view. Turn this on if you use more than one AI provider for delegation — see Chapter 15 · Adding Other AIs. Leave it off if you use a single AI provider.
tycoonagents.themeService.endpoint Advanced: override the Theme Service base URL (https only). Leave empty for the production service — see § 5.6.
§ 10.2 · In-panel Settings tab what each section controls
01

Hook health. Shows whether Claude Code's hooks are installed for this project, with buttons to install or repair them.

02

Path Health. Shows how each UEFN-related path was resolved — override, environment, auto-detected, or NOT FOUND — along with every candidate location that was tried. It also detects whether Epic's Verse VS Code extension is installed and enabled, and warns separately when the extension is installed but disabled rather than missing entirely. You can set explicit path overrides here; they're persisted to .claude/tycoon/uefn-paths.json. A copy-paste diagnostic block is available too, formatted to hand to your own Claude session for guided fixing. See Chapter 14 for the related troubleshooting callout and the environment-variable overrides it honors.

03

Delegation style. Choose between Direct and Team Leads delegation modes, plus a separate Review pass checkbox (on by default) — when enabled, a second agent reviews each specialist's work before it's reported done.

04

Project Plan. Turns the optional phase/task planning feature on or off (see Chapter 12).

05

Agents. Per-role model and agent choices — which model each specialist role runs on. Each agent card also holds the Keywords editor: the word list that decides which specialist a task's description routes to.

06

Orchestrator, Default for all agents, Agent harness. The orchestrator's model, the default model for agents without their own choice, and which harness (Claude Code or Codex) the panel reads from. Design docs installs the design-doc skill and offers Generate and Review buttons, and the Danger zone holds Reset session metrics.

07

Context budget. Controls related to how much context gets passed between agents.

08

Report a bug / Diagnostics. Generates a sanitized diagnostic report you can share when something isn't working — see Chapter 14.

09

Team setup. Export and apply a shared roster/routing shape with teammates, and check readiness on the current machine — see § 10.3 below.

§ 10.3 · Team setup share the shape of your setup, not your machine

Copying an install to a teammate's machine doesn't work: your agent roster lives at absolute paths, your API keys and CLI sessions are yours alone, and vendor CLIs (Claude, Codex) are discovered per machine. Team setup exports the shape of your setup instead — path-free and secret-free by construction, so it's safe to commit.

10

Export team setup writes .claude/tycoon-team.json — the agent roster, per-agent routing (vendor/model plus fallback chains), the names of the env vars each slot needs (never values), which skills and MCP servers are enabled, the delegation mode and parallel limit, an optional plan pointer, and which harness the orchestrator was recorded running on.

11

A teammate who clones the project and opens TycoonAgents sees a "Team setup changed. Apply?" drift notice the next time Settings opens. Apply installs the agents, keywords, skills, delegation mode, and hooks, using project-relative commands so they work regardless of where the project lives on disk. The originator's vendor/model choices only seed routing on a fresh clone (or when local routing is unreadable) — after that, each teammate's own routing choices are kept as-is. MCP installation always needs separate confirmation and is skipped during Apply.

12

Check readiness reports, per agent, a "team: vendor/model · you: vendor/model" line with a "differs" chip when your routing diverges, plus whether it resolves ready, on a fallback, "will use default fallback," or not ready, and which env vars by name are still unset — with a summary count and a harness line. Probe reachability (may use vendor quota) adds a live check and is off by default since it can spend vendor quota.

Note

When only routing changed (not the roster), the drift notice instead reads "Team routing changed (reference only)" and prompts nothing to apply — routing is a reference, the roster is authoritative.
